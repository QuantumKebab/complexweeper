## 二、安装与运行

1. 把 APK 传到手机（数据线、网盘、聊天工具均可），用文件管理器点击安装。
2. 首次安装需在系统设置里允许「未知来源应用」；本 APK 是自签名包，不是商店包。
3. 安装后桌面图标名为「复扫雷」，竖屏启动，无需任何额外权限（不联网、不读通讯录、只写自己的私有目录）。
4. 卸载即清除存档；存档文件在应用私有目录 `complexsweeper.cfg`，记录音效开关、插旗方式与三种模式的历史最好成绩。

## 三、移植方案（技术实现）

原仓库只有 Zig + Win32 的桌面实现，没有任何 Android 工程，因此 Android 平台层是本次新写的，游戏规则与界面语义保持原样。

- **保留原样**：规则层 `game.zig`（连片展开、判据、四种雷型计数、胜负判定等）与官方图集素材、音效数据，均未改动逻辑。
- **Zig 侧**（`android_main.zig` / `softfb.zig` / `platform.zig`）：复刻桌面版的布局与绘制（棋盘、笑脸、LED 计数、顶栏、六种弹出面板），自绘 RGBA 帧缓冲；触摸手势判定与命中测试；存档读写；音效时机。
- **C 侧**（`platform.c`，NDK）：NativeActivity 胶水、EGL/GLES2 上下文与全屏四边形上屏、触摸事件队列、OpenSL ES 音频、zlib 解压、文件读写。
- **渲染路径**：Zig 软件光栅化 → RGBA8888 帧缓冲 → 上传为 GL 纹理 → GLES2 全屏四边形。不依赖字体文件（界面文案全部构建期预渲染成图集，设备端零字体依赖），也不依赖 Java 代码（`hasCode=false`，APK 内无 dex）。
- **屏幕适配**：按屏幕高度自动选择缩放档，另有 100%/200%/300%/400% 手动档；棋盘随屏幕自适应。
- **构建**：Zig 0.14.1 编出 `.o`（`build-obj -fPIC`）→ NDK r26b clang 编 C 并链接成 `.so` → aapt2 打包 → zipalign → apksigner 签名。`android/build.sh` 一条命令可复现整个流程。

## 四、验证范围（重要）

**已验证：**

1. **规则层自检 58 项全过**：直接跑仓库自带的 `selftest.zig`（除版本号来源外未改一行），覆盖随机数确定性、精确配比、纯实/纯虚不变量、连片展开（含大盘 1199 格连片）、组合匹配判据、插旗不限量、旗子保护、胜负判定、闵可夫斯基判据、判定贴图表等。
2. **界面与交互自检 81 项全过**（含矩形顶点表自检：两个三角形必须都有面积、每个顶点的 UV 必须与位置一一对应；把顶点表换回旧写法会立刻报「三角形面积 1440.000 / 0.000」）：在 PC 上用同一份 Zig 代码 + 软件帧缓冲跑了脚本化自检，覆盖初始状态、点击翻开、计时与每秒音效、点脸重开、长按插旗、插旗模式、点数字展开、踩雷判负、胜利自动弹纪录、同成绩不重复弹、主菜单、两种模式子菜单、缩放切换、自定义雷区的四种校验错误、自定义 40×30、换屏、帮助滚动、关于、静音、闵可夫斯基模式、顶栏按钮；存档「写入→重启读回」往返验证通过。
3. **渲染核对**：导出 26 张界面截图（棋盘、菜单、子菜单、自定义、最高分、帮助、关于、胜负等），做了程序化墨迹检查（每行标签、数值、按钮区是否有像素）与人工目视复核；本轮修掉了四个问题，其中第一个是**致命渲染 bug**：④`batch_quad` 把矩形拆成两个三角形时，第二个三角形的两个顶点坐标写重复了（退化三角形），GPU 会整块丢弃——表现就是每个按钮/方块被一条从左下到右上的对角线切开，左上那半正常、右下那半露底。主机自检一直没发现，是因为主机侧走的是像素循环、设备端走的是 GL 顶点缓冲，两条路径各写了一遍。现已把顶点表抽成 `quad_verts.h` 由两边共用，并加了启动自检（会打印两个三角形的面积与 UV 对应关系）。另三个是：①弹出面板沿用上一次面板的几何与标题；②自定义面板每行数值变量未赋值，数字被画到屏幕外；③界面图集是 1024×3888 的纹理，而 GLES2 只保证 `MAX_TEXTURE_SIZE ≥ 2048`，在很多设备上整块图集会上传失败，导致界面元素从别的纹理采样、出现色块错位与文字发白发暗——现已把图集改成 2048×1676、棋盘帧缓冲也限制在 2048 以内，并在运行时打印 `GL_MAX_TEXTURE_SIZE` 与上传结果。
4. **配色与观感**：去掉了面板背后那层现代风格的深色蒙版（改成正统的右下投影），设备端清屏色也从近黑改成与界面同色的 Windows 经典灰，屏幕上不再出现「灰—黑—灰」的横带；面板标题栏的深蓝是原版配色，予以保留。
5. **APK 静态验收**：`aapt2 dump badging` 确认 minSdk 21 / targetSdk 34 / 四种 ABI 原生码 / 启动项为 NativeActivity；`apksigner verify` 通过（v1+v2）；`readelf` 确认四个 `.so` 均无 TEXTREL、按 16 KB 页对齐、依赖项只有系统库（liblog/libEGL/libGLESv2/libandroid/libOpenSLES/libz/libm/libdl/libc）；未定义符号全部落在 NDK 系统库范围内；清单内 `android.app.lib_name=complexsweeper` 与库名一致。

**未验证（如实说明）：**

- **没有在真机或模拟器上实际运行过**。本环境是无 Android 设备、无 KVM 的容器，装不了模拟器，因此「能装、能启动、能玩」这一步没有实测。上述 74 项界面自检跑在 PC 的软件帧缓冲上，验证的是同一份游戏与界面代码，但**不等于设备端实测**。
- Android 5.0 兼容性的依据是：minSdk 21 + 只使用 API 21 以内就存在的接口（NativeActivity / EGL / GLES2 / OpenSL ES / zlib），没有调用任何更高版本的 API；这属于静态依据，未在 Android 5 实机验证。
- 触摸手感（长按阈值 0.4 秒）、不同屏幕比例下的自动缩放档位、OpenSL ES 音效在具体机型上的表现，都需要真机体验后再微调。
- **双指捏合缩放尚未实现**：目前放大/缩小靠顶栏按钮与菜单，放大后靠单指拖动平移（这两项都已在自检里逐项验证）。捏合需要把多点触控从 C 层一路接到游戏层，本环境无法真机验证，故未纳入本轮；如果需要，我可以补上并给出可复现的自检。
